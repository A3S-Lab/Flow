# 节点目录

Flow 1.0 处理两层节点。`WorkflowDagNode` 保存编辑器里的图节点，`RuntimeCommand` 表达引擎下一步要提交的持久决定。图节点经过宿主编译后，可以生成一个或多次运行命令。两层对象不能直接互换。

## 节点配置示例

下面的配置区覆盖 14 种持久命令与两种结构容器。字段按身份、输入、重试和终态条件分组，关联选项会随着策略变化显示。表单会保留每个节点的本页草稿，并把错误放到对应字段下。步骤与子工作流批次支持增删成员，生成的 JSON 通过校验后才能复制。

桌面布局把节点目录与配置区并排，JSON 预览放在完整表单之后，避免两列字段被压得过窄。移动端会把节点目录改成横向选择，并把字段收成单列。分类标签支持方向键、`Home` 和 `End`，所有控件都能用键盘操作。这个区域只解释当前页面的配置契约，不会创建或保存工作流。

## 支持边界

| 层级     | Flow 1.0 接受的内容                                  | Flow 负责的检查                            | 仍由宿主负责                       |
| -------- | ---------------------------------------------------- | ------------------------------------------ | ---------------------------------- |
| 图节点   | 任意非空字符串 `data.type`                           | 节点身份、边、作用域、环路与稳定顺序       | 节点属性模式、授权与执行器         |
| 容器节点 | `iteration`、`loop`、`iteration-start`、`loop-start` | 父子关系、起始节点与作用域内连边           | 迭代数据、停止条件、并发与输出聚合 |
| 运行命令 | 14 个 `RuntimeCommand` 变体                          | 历史事件、重放一致性、暂停、终态与并发写入 | 外部副作用、凭据、租户与逻辑幂等   |

`start`、`end`、`llm`、`code`、`tool` 或其他名字可以保存在 `data.type` 中。结构编译器不会为这些名字附加执行器，也不会为它们推断属性。宿主应维护允许列表和版本化属性模式，再把节点编译到下表中的持久命令。

## 14 种持久命令

| 节点用途     | Rust 构造入口             | JSON `type`             | 运行结果                   |
| ------------ | ------------------------- | ----------------------- | -------------------------- |
| 单步骤       | `schedule_step()`         | `schedule_step`         | 执行一个宿主步骤并保存输出 |
| 步骤批次     | `schedule_steps()`        | `schedule_steps`        | 先保存全部身份，再并发推进 |
| 记录进度     | `record_progress()`       | `record_progress`       | 追加一条带稳定 ID 的进度   |
| 关联外部操作 | `link_child_operation()`  | `link_child_operation`  | 保存宿主管理的操作引用     |
| 定时等待     | `wait_until()`            | `wait_until`            | 暂停到 UTC 截止时间        |
| 信号等待     | `wait_for_signal()`       | `wait_for_signal`       | 消费最早的同名未用信号     |
| 外部 Hook    | `create_hook()`           | `create_hook`           | 等待令牌路由的接收或撤回   |
| 单个子工作流 | `start_child_workflow()`  | `start_child_workflow`  | 启动或等待一个第一类子运行 |
| 子工作流批次 | `start_child_workflows()` | `start_child_workflows` | 持久声明最多 64 个子运行   |
| 续段         | `continue_as_new()`       | `continue_as_new`       | 关闭当前历史并建立后继段   |
| 成功         | `complete()`              | `complete`              | 写入成功终态与 JSON 输出   |
| 失败         | `fail()`                  | `fail`                  | 写入应用失败终态           |
| 完成取消     | `cancel()`                | `cancel`                | 完成已经持久化的清理式取消 |
| 超时         | `timeout()`               | `timeout`               | 写入截止时间和可选理由     |

每次 `run_workflow()` 只返回一个命令。引擎提交命令产生的事件后重新调用工作流，工作流从新历史决定下一步。批次命令仍是一个决定，批次中的成员由引擎按各自身份保存和推进。

## 图节点公共属性

```json
{
  "id": "charge-order",
  "type": "custom",
  "position": { "x": 320, "y": 120 },
  "data": {
    "type": "service-call",
    "operation": "billing.charge",
    "retry_profile": "payment"
  }
}
```

| 属性         | 必填 | 执行语义                                                      |
| ------------ | ---- | ------------------------------------------------------------- |
| `id`         | 是   | 图内稳定身份，不能为空且不能重复                              |
| `data`       | 是   | 完整语义对象，会进入执行摘要                                  |
| `data.type`  | 是   | 非空字符串，交给宿主选择属性模式与执行器                      |
| `parentId`   | 否   | 容器身份，只能指向 `iteration` 或 `loop`                      |
| 其余顶层字段 | 否   | 作为展示字段无损保留，例如 `type`、`position`、宽高和选中状态 |

展示字段不会改变 `execution_digest()`。`data`、`parentId`、边端点和边语义数据会改变摘要。节点数组的原始顺序也不会改变计划，同一作用域中可同时就绪的节点按稳定 ID 排序。

## 边的公共属性

| 属性           | 必填 | 说明                               |
| -------------- | ---- | ---------------------------------- |
| `id`           | 是   | 图内唯一且非空                     |
| `source`       | 是   | 已存在的起点节点 ID                |
| `target`       | 是   | 已存在的终点节点 ID                |
| `sourceHandle` | 否   | 编辑器中的起点连接口               |
| `targetHandle` | 否   | 编辑器中的终点连接口               |
| `data`         | 否   | 分支标签或其他宿主语义，会进入摘要 |
| 其余顶层字段   | 否   | 展示数据，无损往返                 |

边不能连接节点自身，也不能跨越顶层与容器内部作用域。任何作用域出现环路都会使 `execution_plan()` 失败。

## 从图节点编译到持久命令

下面的映射是宿主代码示例。`service-call` 是这个宿主自己的节点类型，并非 Flow 预注册名称。

```rust
match node.node_type() {
    "service-call" => {
        let operation = node.data()["operation"]
            .as_str()
            .ok_or_else(|| FlowError::Runtime("missing operation".into()))?;

        Ok(ctx.schedule_step(
            format!("node:{}", node.id()),
            operation,
            resolved_input,
        ))
    }
    node_type => Err(FlowError::Runtime(
        format!("unsupported node type {node_type}"),
    )),
}
```

发布前应完成属性校验、变量解析、权限检查和执行器版本固定。运行期间只读取已经发布的图和绑定，不能用修改后的画布解释旧历史。

## 节点身份规则

稳定 ID 要来自发布图或确定性索引。不要在重放函数里生成 UUID、读取当前时间或按完成顺序编号。第一次提交后，步骤名、输入、重试策略、等待截止时间、信号名、Hook 令牌、子工作流定义和取消策略都成为历史的一部分。后续重放返回同一 ID 却改变这些属性时，引擎会以非确定性错误停止。
