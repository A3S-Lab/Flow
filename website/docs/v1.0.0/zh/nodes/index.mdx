# 节点目录

A3S Flow 1.0 提供 18 个可以直接放到画布上的节点。每个节点都由 manifest 声明字段、默认值、端口、运行绑定和持久身份规则。React 组件、Vue Hook、CLI、Skill 和本页文档读取同一份清单。

`iteration-start` 与 `loop-start` 是容器内部入口。它们由编辑器随容器创建，不出现在节点选择器中，也不能放到顶层画布。

## 节点工作台

下面的工作台使用 `@a3s-lab/flow-ui` 的公开组件。选择一个节点后，画布卡片和右侧配置面板会读取同一个节点对象。标题、说明和字段修改会立即反映到预览中。等待、回调、批次、子工作流和容器使用各自的专用控件。

## 六个分组

| 分组       | 节点                                                                                                                              | 负责的事情                             |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 流程入口   | [开始](./start)、[条件分支](./condition)                                                                                          | 接收输入并选择确定性的控制分支         |
| 任务与工具 | [执行任务](./step)、[批量任务](./batch)                                                                                           | 调用宿主任务并保存结果、错误和重试状态 |
| 等待与审批 | [定时等待](./wait)、[回调与审批](./hook)、[信号等待](./signal)                                                                    | 释放 worker，等待时间或外部输入        |
| 子流程     | [外部任务引用](./child-operation)、[子工作流](./child-workflow)、[子工作流批次](./child-workflows)、[后续运行](./continue-as-new) | 管理长任务引用、第一类子运行和历史续段 |
| 运行状态   | [运行进度](./progress)、[成功结束](./complete)、[失败结束](./fail)、[取消运行](./cancel)、[超时结束](./timeout)                   | 写入可检查状态并关闭运行段             |
| 子画布容器 | [遍历集合](./iteration)、[条件循环](./loop)                                                                                       | 建立独立图作用域，约束父子关系和连线   |

## 运行绑定

有 `runtimeBinding` 的节点会编译成 A3S Flow 的持久运行命令。`flow.start` 和 `flow.condition` 在图执行层处理。`iteration` 与 `loop` 负责子画布结构，宿主决定如何把每轮工作编译成步骤或子工作流。

任务和等待类节点通常使用图节点 ID 作为持久身份。批量节点还会把成员 key 加入身份。已有运行开始后，修改这些 ID 会让重放无法匹配原历史。

每个节点的独立页面都列出以下内容。

- 适用场景和运行方式
- 全部字段、默认值、控件、范围、可选值和显示条件
- 控制端口与数据端口
- 运行绑定和持久身份规则
- 完整节点 JSON、CLI 命令和 Skill 提示
- 与恢复、重试、取消和容器作用域有关的注意事项

## 从 CLI 核对清单

安装包中的清单与前端组件一起发布。先查看当前版本，再创建节点。

```bash
a3s-flow nodes --pretty
a3s-flow node flow.step --pretty
a3s-flow new flow.step --id charge-order --pretty
```

把节点加入图后，运行 `validate`、`compile` 和 `digest`。CLI 会检查字段、端口、作用域、环路和确定性执行顺序。
