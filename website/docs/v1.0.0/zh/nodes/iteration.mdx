# 遍历集合 `iteration`

遍历容器为集合中的每个成员建立相同的子画布作用域。`items` 表达式在进入容器前得到确定集合，宿主再把子图编译成稳定步骤或子工作流。它适合成员处理逻辑相同、每项都需要清楚输入与结果边界的场景。成员规模很大时应先分窗，避免一次运行保存过多任务。

## 子画布结构

每个容器只能有一个内部 `iteration-start`，其 ID 必须等于 `start_node_id`。内部入口与其他子节点都把 `parentId` 设为容器节点 ID。入口的 `item` 数据端口提供当前成员，`next` 控制端口连接第一项工作。容器内至少还要有一个可执行节点，所有边的两端都留在同一作用域。

普通 DAG 不能画回边。遍历行为由容器表达，外层控制从 `in` 进入，所有成员完成后从 `done` 继续。宿主负责成员变量、并发、结果聚合和失败策略，因此发布前应明确是串行、限流并行还是以子工作流执行，并确保顺序与摘要在相同输入下保持稳定。

## 成员身份与验证

集合成员需要可重复得到的业务身份，不能依赖随机排序或实时查询顺序。测试应覆盖空集合、单成员、重复业务键、部分失败、进程恢复、并发限制和结果顺序。校验提示跨作用域边时，检查每个子节点的 parentId 与边端点。需要按条件重复同一状态时使用循环容器，不要把不断变化的集合塞进一次遍历。
