# 条件分支 `flow.condition`

条件节点根据已经提交的数据选择一条控制路径。它适合订单状态、审核结果、计数阈值和上游任务结果等确定性判断。节点不会请求远程服务，也不会读取新的系统时间或随机值。需要外部信息时，应先用任务节点取得结果并写入历史，再让条件表达式读取该结果。

## 输入与表达式

`input` 保存当前待判断值，也可以通过数据端口由上游节点提供。`expression` 使用受限表达式读取启动输入、当前值或已保存结果。发布前要用真值、假值、缺失字段、空数组和异常类型分别验证，确保类型变化不会让分支含义漂移。复杂判断宜拆成若干具有业务名称的条件节点，便于从事件和图结构还原决定过程。

`matched_label` 与 `otherwise_label` 只改变画布文案，稳定端口仍是 `matched` 和 `otherwise`。修改标签不会改变摘要中的连接身份，修改表达式会改变执行语义。两条控制端口都应有明确去向。业务允许某一分支直接结束时，也要显式连接完成、失败、取消或超时节点。

## 接线与排查

入站控制边连接 `in`，可选数据边连接 `value`。条件为真时开放 `matched`，其余结果进入 `otherwise`。测试应检查每个分支最终可达终态，并确认没有从下游画回条件节点的回边。校验提示表达式路径有误时，先核对上游输出形状和字段路径，再查看连接到 `value` 的数据是否覆盖了节点内的 `input`。
