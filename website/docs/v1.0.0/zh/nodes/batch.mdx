# 批量执行任务 `flow.batch`

批量任务节点一次声明多项可以独立推进的宿主任务，并按声明顺序汇总结果。它适合数量已知、成员边界清楚的小批处理，例如同时检查若干资料或调用一组固定工具。成员集合非常大或需要分页恢复时，应按稳定游标拆成多批，或使用遍历容器建立更清楚的成员作用域。

## 成员配置

`steps` 中每个成员都有 `step_key`、`step_name`、`input_mapping`、`max_attempts`、`retry_delay_ms` 和 `on_exhausted`。`step_key` 在节点内必须唯一，并与图节点 ID 共同形成持久步骤身份。成员完成顺序可能不同，但不能根据完成先后重新编号、排序或复用 key。编辑已有运行对应的成员列表时，要保留原成员身份和语义位置。

每个 `input_mapping` 独立构造参数，重试字段也按成员生效。只要有成员选择 `continue_workflow`，节点就会提供 `recoverable_failure` 与 `errors`，后续可以检查哪些成员失败。默认的 `fail_run` 会在相应成员耗尽尝试后结束运行。宿主任务仍需处理至少一次交付，并为每个成员生成包含运行、节点、成员和尝试身份的幂等键。

## 结果与容量

全部成员解析后，控制从 `done` 继续，`results` 按声明顺序提供结果。失败分支同样保持成员顺序，不能依靠数组位置推断完成时间。发布前应验证空列表、重复 key、部分失败、全部失败、进程恢复和大结果体积。每项输出较大时只保存对象引用。批量规模应服从宿主并发与队列容量，避免一个节点瞬间提交超过下游可以承受的任务数。
