# 执行任务 `flow.step`

任务节点把一次外部工作交给宿主注册的处理器，例如模型调用、MCP 工具、HTTP 请求、数据库写入或业务服务。Flow 保存调度请求、尝试次数和最终结果，宿主负责凭据、权限、网络访问与真实副作用。`step_name` 必须与宿主注册表中的稳定名称一致，发布流程应在启动运行前验证该处理器可用。

## 输入与重试

`input` 表达式从启动输入或上游结果构造任务参数。提交到历史的输入会在重试时保持一致，因此不要把当前时间、随机数或进程内可变状态直接放进表达式。需要这些值时，由宿主任务生成并把结果提交回来。大型文件、模型输出和二进制内容宜传递对象引用，避免让事件历史承担不必要的体积。

`max_attempts` 包含首次执行，`retry_delay_ms` 表示下一次尝试前的等待时间。`on_exhausted` 选择 `fail_run` 时，尝试耗尽会结束运行。选择 `continue_workflow` 时，节点开放 `failed` 控制端口和 `error` 数据端口，后续图可以补偿、降级或转人工处理。外部系统幂等键应由运行 ID、节点 ID 和尝试身份构成。

## 端口与运行检查

成功结果提交后，`success` 与 `result` 才可供下游使用。任务在外部操作完成后、结果写入历史前遇到进程退出时可能再次交付，所以测试需要覆盖重复调用。只有启用继续失败分支时才连接 `failed` 与 `error`。上线前还要检查超时策略、错误脱敏、处理器版本路由、补偿路径和重试上限，避免永久错误在队列中反复消耗资源。
