# 关联外部任务 `flow.child-operation`

外部任务节点把其他系统拥有的长任务引用写入历史，例如渲染作业、数据导入、批处理或云端构建。它只登记关系，不启动、不轮询，也不等待外部任务。需要 Flow 管理完整启动、终态和取消传播时，应使用子工作流节点。

## 引用字段

`reference_id` 是父运行内稳定的引用身份，通常与图节点 ID 保持清楚对应。`kind` 说明宿主定义的任务类别，`operation_id` 使用外部系统实际分配的身份。`flow_run_id` 可选，用于关联另一个 Flow 运行。`metadata` 只放小型、非敏感且便于检查的信息，例如租户内可见的资源类型或对象引用。

引用事件提交后，控制从 `linked` 继续，`child` 数据端口提供结构化引用。后续状态查询、结果收集和取消需要显式连接任务、Hook 或信号节点。图中不应假设登记成功代表外部任务已经成功，也不能根据画布节点状态伪造外部进展。

## 所有权与检查

宿主需要验证外部任务确实存在、调用者有权引用，并控制哪些元数据可以写入历史。测试应覆盖重复登记、错误 operation ID、外部任务已经结束、引用系统暂时不可用和进程恢复。监控页面应清楚区分已关联、正在执行、已经结束和无法查询，不能把引用事件当成结果事件。
