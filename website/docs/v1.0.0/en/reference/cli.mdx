# CLI commands

Flow 1.0 publishes one command-line program, `a3s-flow-native-compiler`. It analyzes dependencies for a native TypeScript entrypoint and compiles that entrypoint into an executable artifact a host can invoke. Run creation, signal delivery, hook resumption, and history inspection remain Rust API operations.

## Prerequisites and installation

Installation requires a Rust toolchain and Cargo. The compiler invokes Bun and looks for `bun` on `PATH` by default.

```sh
cargo install a3s-flow --version 1.0.0 --locked \
  --bin a3s-flow-native-compiler

a3s-flow-native-compiler --version
a3s-flow-native-compiler --help
```

A production image should pin the crate version, use `--locked`, and pin an audited Bun executable. Flow includes the executable contents in compiler identity. If that file changes while a command is running, the command fails.

## Command surface

```text
a3s-flow-native-compiler capabilities
a3s-flow-native-compiler dependencies <entrypoint.ts>
a3s-flow-native-compiler compile <entrypoint.ts> -o <artifact>
```

| Command        | Standard output              | File changes                                               |
| -------------- | ---------------------------- | ---------------------------------------------------------- |
| `capabilities` | One JSON capability document | None                                                       |
| `dependencies` | One JSON dependency manifest | Uses a guarded temporary directory and cleans it afterward |
| `compile`      | No output on success         | Creates one artifact at the requested path                 |
| `--help`       | Help text                    | None                                                       |
| `--version`    | Crate version                | None                                                       |

No arguments prints help and exits successfully. `-h` and `help` are equivalent to `--help`; `-V` and `version` are equivalent to `--version`. The public command surface is closed. Extra arguments and alternate option spellings are rejected.

## `capabilities`

Hosts use this command to verify the compiler protocol before accepting source.

```sh
a3s-flow-native-compiler capabilities
```

Version 1.0.0 emits this structure.

```json
{
  "protocol": "a3s.flow.native_ts.compiler.v1",
  "dependencyManifest": true
}
```

| Field                | Meaning                                                  |
| -------------------- | -------------------------------------------------------- |
| `protocol`           | Compiler command protocol; hosts compare the exact value |
| `dependencyManifest` | Whether this binary supports `dependencies`              |

Reject an incompatible capability during deployment admission. Waiting until a workflow run needs replay leaves a durable run that the host cannot execute.

## `dependencies`

The dependency command asks Bun to resolve the entrypoint and its complete source graph.

```sh
a3s-flow-native-compiler dependencies src/workflows/order.ts
```

It writes one compact JSON object followed by a newline.

```json
{
  "protocol": "a3s.flow.native_ts.dependencies.v1",
  "compilerIdentity": "bun-sha256:...",
  "files": [
    "package.json",
    "src/shared/money.ts",
    "src/workflows/order.ts",
    "tsconfig.json"
  ]
}
```

| Field              | Rule                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| `protocol`         | Fixed dependency-manifest protocol v1                                                               |
| `compilerIdentity` | Opaque identity derived from the resolved Bun executable                                            |
| `files`            | UTF-8 paths relative to the current directory, forward-slash separated, strictly sorted, and unique |

The list contains the entrypoint and every source reported by Bun. For each source, the compiler also walks parent directories up to the working root and includes any `bun.lock`, `bun.lockb`, `bunfig.toml`, `package.json`, or `tsconfig.json` file it finds. A file whose size changes during scanning causes the command to fail.

The entrypoint and every resolved dependency must stay inside the current working directory. An absolute entrypoint is accepted only when its canonical file is still within that root. Symlink escapes, directory entrypoints, non-UTF-8 paths, and non-portable path components are rejected.

`NativeTsRuntime` performs additional admission checks for document size, entry count, path length, traversal, ordering, duplicates, and entrypoint coverage. The verified manifest participates in source hashing and artifact cache identity.

## `compile`

The compile command produces a native executable artifact.

```sh
mkdir -p .a3s/flow/native-ts

a3s-flow-native-compiler compile \
  src/workflows/order.ts \
  -o .a3s/flow/native-ts/order-workflow
```

Argument order is fixed, and the output option must be `-o <artifact>`. The output directory must already exist and the target file must not exist. The compiler refuses to overwrite a file, which prevents competing cold-cache processes from replacing one another's output.

A successful artifact implements this runtime protocol.

- Accept `--a3s-flow-runtime`.
- Read one `NativeRuntimeRequest` JSON object from standard input.
- Write one `NativeRuntimeResponse` JSON object to standard output.
- Resolve workflow requests by the request `exportName`.
- Resolve step requests from an exported `steps` object by `payload.step_name`, then try a same-named top-level export.

A handler may return synchronously or return a Promise. `undefined` becomes JSON `null`. Runtime errors produce an `ok: false` response, with the error message limited to 4096 characters.

Compilation uses Bun compile mode and bundles dependencies. The artifact is configured not to auto-load dotenv, Bun configuration, TypeScript configuration, or `package.json` at invocation time. Runtime behavior therefore comes from the bundled source graph and request.

## Working directory

Both source commands treat the process working directory as the security boundary and logical path root. Run them from the TypeScript project root so entrypoints, lock files, and configuration have stable relative names.

```sh
cd services/order-workflows
a3s-flow-native-compiler dependencies src/main.ts
```

CI and production compilation should use the same directory layout. Moving the absolute project root preserves relative manifest names, while omitting a lock file or configuration file changes the source graph and cache identity.

## `A3S_FLOW_BUN`

Set `A3S_FLOW_BUN` when `bun` is not on `PATH` or when the host requires an explicit executable.

```sh
A3S_FLOW_BUN=/opt/a3s/toolchain/bin/bun \
  a3s-flow-native-compiler dependencies src/main.ts

A3S_FLOW_BUN=/opt/a3s/toolchain/bin/bun \
  a3s-flow-native-compiler compile src/main.ts -o build/workflow
```

The value may be a command name resolved through `PATH` or a path containing a directory. The compiler resolves it to a regular executable, fingerprints its contents, and verifies its metadata again when the command finishes.

## Exit codes and diagnostics

| Exit code | Meaning                                                      | Output                                                                       |
| --------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `0`       | Command succeeded, or no arguments printed help              | Command result goes to standard output                                       |
| `2`       | Argument, file, Bun, dependency-scan, or compilation failure | A diagnostic prefixed with `a3s-flow-native-compiler` goes to standard error |

Bun diagnostics are inherited on standard error. The compiler then adds the exit status and resolved Bun path. Automation should use the exit code, not parse a particular diagnostic sentence that can change with the underlying tool.

If the compiler parent exits or cancels the process, a supervisor terminates and reaps Bun. A separate guard owns temporary-workspace cleanup. Failed compilation output is removed as well.

## Common failures

| Diagnostic shape                     | Cause                                             | Action                                                         |
| ------------------------------------ | ------------------------------------------------- | -------------------------------------------------------------- |
| `unknown command`                    | Command is outside the public set                 | Run `--help` and use an exact command                          |
| `usage: ... compile`                 | Argument order or output option is wrong          | Use `compile <entrypoint.ts> -o <artifact>`                    |
| Bun not found                        | `PATH` has no Bun or the override is invalid      | Set `A3S_FLOW_BUN` to an executable absolute path              |
| Entrypoint outside working directory | Wrong root or a symlink escapes it                | Change to the project root and pass an entrypoint inside it    |
| Output already exists                | The compiler refuses replacement                  | Use a fresh content-addressed target                           |
| Output directory missing             | The compiler does not create caller-owned parents | Create the explicit parent directory first                     |
| Unresolved import                    | Bun cannot resolve a dependency                   | Repair imports, install dependencies, and verify the lock file |
| Dependency changed during scanning   | Another process rewrote source during the scan    | Retry from a stable checkout or read-only source snapshot      |

For host integration, call `capabilities` first, use `dependencies` for an early graph check, and then let `NativeTsRuntime::preflight()` exercise the same cache and compile path used by execution.
