# Durable primitives

Flow represents waiting and recovery as typed commands in history. A suspended run does not require a resident workflow task.

## Bounded retries

Retry policy is part of the replayed step command. Exponential policies use deterministic full jitter derived from immutable run, step, and attempt identity.

```rust
use a3s_flow::RetryPolicy;
use std::time::Duration;

let retry = RetryPolicy::exponential(
    8,
    Duration::from_secs(1),
    Duration::from_secs(30),
);

Ok(ctx.schedule_step_with_retry(
    "charge-card",
    "charge_card",
    input,
    retry,
))
```

The maximum attempt count includes the first execution. Exhaustion fails the run by default, or it can return control to workflow code with `continue_workflow_on_failure`.

## Timers

`wait_until` records a stable wait ID and UTC deadline. The scheduler wakes the run after the deadline without holding an in-memory task.

```rust
Ok(ctx.wait_until("settlement-window", resume_at))
```

Workflow code checks `ctx.wait_completed("settlement-window")` before issuing the next command.

## Named signals

Signals are declared by name and consumed through a stable wait ID. Delivery before or after suspension produces the same durable pairing.

```rust
if let Some(payload) = ctx.signal_payload("approval") {
    return Ok(ctx.complete(payload.clone()));
}

Ok(ctx.wait_for_signal("approval", "order.approved"))
```

## Hooks and callbacks

Hooks expose a token-routed completion boundary for human approval, webhooks, and other external callbacks.

```rust
if let Some(payload) = ctx.hook_payload("review") {
    return Ok(ctx.complete(payload.clone()));
}

Ok(ctx.create_hook(
    "review",
    callback_token,
    serde_json::json!({ "kind": "approval" }),
))
```

The host must keep callback tokens secret and authorize the route before calling Flow.

## Cancellation

Graceful cancellation enters `Cancelling`, lets workflow code schedule stable cleanup steps, and records one terminal outcome after cleanup. Force cancellation remains an explicit host choice.

## Continue as new

Long-running workflows can close one history segment and create a linked successor with the same exact workflow authority.

```rust
Ok(ctx.continue_as_new(next_input))
```

Use continuation for bounded history, not as a substitute for child workflows or retries.
