# Production operations

Production Flow hosts need explicit persistence, dispatch, runtime compatibility, observability, and retention policy.

## Dispatch

A3S Boot task management is the recommended production dispatcher. Enable the `boot` feature to use `BootFlowTaskManager` and a typed `BootFlowTaskPolicy`.

Embedded compatibility queues and `FlowWorker` remain available for bounded local or migration scenarios. PostgreSQL and local-file queue implementations must not become a second workflow history.

## Runtime build routing

`RuntimeBuildId` is part of workflow authority. A worker must prove compatibility before mutating a run.

Use `RuntimeBuildTaskRouter` when old and new builds run together. Route each task to a compatible worker pool and reject unknown builds before step execution.

## Replay-safe patches

An immutable `WorkflowPatchId` records which branch a history selected. Workflow code can preserve the old branch for existing runs while new runs select the new branch.

Do not remove an old branch until every history that can reference it is retired or continued onto a compatible segment.

## Observability

Observers run after a commit. They can fan out to telemetry, an A3S Event bridge, or a local JSONL audit sink without becoming state authority.

```rust
use a3s_flow::{FanoutFlowEventObserver, FlowEngineBuilder};

let observer = FanoutFlowEventObserver::new(vec![metrics, audit]);
let engine = FlowEngineBuilder::new(store, runtime)
    .with_observer(observer)
    .build();
```

Observer failure must not rewrite committed history. Repair downstream projections from the event sequence.

## Readiness checklist

- Migrations run through an explicit owner before serving starts.
- Every worker advertises the runtime builds it can replay.
- Step side effects use stable idempotency keys.
- Scheduler and queue leases have bounded timeouts and dead-letter visibility.
- Callback routes authenticate tokens before calling Flow.
- Metrics include run status, suspension kind, retry attempt, queue delay, and append conflict rate.
- Backups and retention restores are tested from real persisted history.

The repository [cookbook](https://github.com/A3S-Lab/Flow/blob/main/docs/COOKBOOK.md) contains complete host recipes.
