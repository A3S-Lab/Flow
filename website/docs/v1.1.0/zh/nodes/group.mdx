# 分组 `group`

分组容器把一组节点收进一个子画布，外层画布只看到一个步骤。控制从 `in` 进入，子画布执行一次，完成后从 `done` 继续。它适合把一段相对独立的工作放在一起展示和审阅，例如一份子计划、一个地区的评估或一组报关材料的处理，而不必拆成一个有独立历史的子工作流。

## 结构

`start_node_id` 必须指向容器内唯一的 `group-start`。所有子节点使用容器 ID 作为 parentId，内部入口的 `next` 连接第一项工作。边不能跨出容器，外层节点读取的是容器本身的结果，不直接连到容器里的某个节点。分组里可以再放遍历集合或条件循环，嵌套的容器同样各自有起始节点。

## 和子工作流的区别

分组只描述图结构，不生成运行命令，宿主决定如何把子画布编译成步骤。它和外层共用同一段运行历史，取消外层运行时分组里的工作一起停止。需要自己的历史、状态和取消策略时，使用[子工作流](./child-workflow)。需要对一组输入重复执行时，使用[遍历集合](./iteration)。重复次数由条件决定时，使用[条件循环](./loop)。

## 检查清单

确认容器里至少有一个可执行子节点，起始节点只有一个，且所有连线都在同一个作用域内。测试应覆盖分组里的任务失败、外层取消和进程重启后从历史恢复。
