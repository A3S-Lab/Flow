# 开始后续运行 `flow.continue-as-new`

续段节点关闭当前历史段，并用新输入创建同一工作流的后续运行。它适合长期轮询、分页处理、周期维护和需要限制单段历史长度的过程。旧运行会提交续段终态，新的运行继承工作流定义、运行时构建和补丁标记，然后从开始节点重新执行。

## 后续输入

`input` 表达式构造新运行的启动数据。需要继续分页时，应携带稳定游标、累计结果引用和已经确认的业务状态。不要只依赖进程内计数或当前页面位置。输入应保持小而完整，让新历史段可以独立恢复，也能从审计记录解释它从哪里接续。

`successor` 端口表达作者图中的后继关系，旧运行提交终态后不会沿该端口继续执行普通节点。未消费信号存在时，引擎会拒绝续段，避免悄悄丢失已经到达的业务消息。取消清理期间也不能创建后续运行。需要并行独立过程时应使用子工作流，避免把续段误当成分叉工具。

## 历史与发布检查

测试应覆盖游标边界、空页、最后一页、重复续段请求、进程在创建后继前退出以及新旧运行关联。监控需要把各历史段串成一条业务链，并分别显示段 ID 与原始业务身份。发布新版本时确认后继仍被路由到兼容 worker，保留旧段重放所需代码，避免长运行在续段边界失去执行入口。
