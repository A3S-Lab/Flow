# 启动子工作流 `flow.child-workflow`

单个子工作流节点启动并等待一个拥有独立输入、事件历史、信号和终态的运行。父运行先把子项请求写入历史，再由调度器创建或恢复子运行。子项解析后，父运行重新投递，并从完成端口取得真实终态。复杂业务可以用它把清楚的责任边界拆成可独立观测与恢复的过程。

## 身份与定义

`child_id` 在父运行内保持稳定，并与图节点 ID 一起固定父子关系。`spec` 包含工作流名称、版本、运行时类型、入口和可选构建路由。`input` 表达式生成子项启动数据。相同 child ID 再次重放时，spec 与输入必须保持一致，不能用同一身份启动另一套定义或不同业务对象。

`cancellation_policy` 选择 `request_cancellation` 时，父项取消会向子项发出取消请求，并等待其清理完成。选择 `abandon` 时，父项结束后子运行可以独立继续。使用 abandon 前要确认子项有独立所有者、访问路径和保留策略，避免运行失去可见责任方。

## 结果与故障处理

子项解析后，控制从 `completed` 继续，`outcome` 提供成功、失败、取消或超时结论。父图应检查终态再决定自己的结果，不能默认完成事件等于成功。测试需要覆盖重复启动、子项失败、父项取消、abandon、调度器重启、版本路由和结果体积。子项输出较大时返回对象引用，父项只保存继续判断所需信息。
