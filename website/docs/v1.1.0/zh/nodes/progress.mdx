# 更新运行进度 `flow.progress`

进度节点把可检查的里程碑、数量和短说明写入运行历史。它适合批处理完成数、导入阶段和长任务状态，让控制面在运行没有结束时展示已确认进展。进度只提供观测信息，不替代决定后续分支所需的业务状态，也不会调用宿主任务。

## 进度字段

`progress_id` 是一次更新的稳定身份，通常使用图节点 ID。`completed` 表示已完成数量，`total` 可选且有值时不能小于已完成数量。`message` 用于简短说明当前里程碑，`details` 保存小型结构数据或对象引用。所有表达式都应读取已经持久化的数据，避免重放产生不同进度内容。

提交成功后，控制从 `recorded` 继续。相同 `progress_id` 不应写入彼此冲突的内容。需要多次上报时，可以给各里程碑使用不同稳定节点，或在受控循环中把明确的迭代身份带入进度键。高频细粒度遥测应写入指标系统，不能把每个字节或每个模型 token 都变成历史事件。

## 展示与验证

界面应说明进度来自最近一次已提交事件，并区分运行中、等待、失败和终态。测试要覆盖未知总量、零值、完成数超过总量、重复提交、进程恢复和大型 details。发布前还应确定进度保留策略、访问权限和本地化文案，确保操作者看到的数字能够对应真实业务单位。
